## Root Cause Analysis (Updated)
之前报告为 CORS 问题，实际根因更精确：

### 登录失败的真实原因：Cookie Secure 标志
1. 表单通过传统 POST 提交（不涉及 CORS）
2. 服务器以 `NODE_ENV=production` 运行
3. Cookie 设置 `secure: true` (src/routes/admin.routes.ts:64)
4. HTTP 协议下浏览器拒绝存储 Secure cookie
5. 服务器 302 重定向到 /admin
6. 浏览器无 cookie → 服务器再次重定向到 /admin/login

### 验证步骤
```bash
# curl 测试 - 证明服务器登录接口正常
curl -v -X POST "http://192.168.0.29:3011/admin/login" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "username=admin&password=admin123"
# 返回 302 + Set-Cookie: token=xxx; Secure; HttpOnly; SameSite=Lax

# document.cookie 测试 - 证明绕过 Secure 标志后登录正常
document.cookie = 'token=xxx; path=/; max-age=604800; SameSite=Lax';
# 成功进入仪表盘
```
