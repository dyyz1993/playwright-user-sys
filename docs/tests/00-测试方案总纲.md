## 1. 测试原则

### 1.1 核心原则

| 原则 | 说明 | 示例 |
|------|------|------|
| **真实性第一** | 测试必须反映真实代码行为，不修改代码迎合测试 | ✅ 真实调用函数，断言真实结果<br>❌ Mock被测函数，断言调用次数 |
| **问题即记录** | 发现Bug时记录问题，不隐藏，不绕过 | 使用 `test.skip()` 记录问题场景 |
| **独立可运行** | 每个测试可独立运行，不依赖执行顺序 | 不依赖共享状态，每个测试独立准备数据 |
| **快速反馈** | 测试应快速执行，失败时给出明确信息 | 使用有意义的测试名称，清晰的断言消息 |
| **可维护性** | 测试代码也是代码，需要保持清晰 | 复用测试辅助函数，避免重复 |

### 1.2 Mock 策略

```
┌─────────────────────────────────────────────────────────────────┐
│                      Mock 决策树                                │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  被测对象是什么？                                                │
│     │                                                          │
│     ├── Models (数据库操作)                                     │
│     │     └── 使用真实内存数据库 (:memory:)                      │
│     │         Mock: 外部服务 (gRPC, webhook, HTTP)              │
│     │                                                          │
│     ├── Services (业务逻辑)                                     │
│     │     └── 真实执行业务逻辑                                   │
│     │         Mock: Models层、外部服务                           │
│     │                                                          │
│     ├── Controllers (请求处理)                                  │
│     │     └── 真实执行请求处理逻辑                               │
│     │         Mock: Services层、Models层                         │
│     │                                                          │
│     └── Routes (集成测试)                                      │
│           └── 真实执行完整请求流程                               │
│               Mock: 仅最外层依赖 (如第三方API)                   │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 1.3 ✅ 正确示例

```typescript
// Models层 - 使用真实数据库
test('扣除点数应该更新余额', async () => {
  const user = await UserModel.create({
    username: 'test_user',
    credits: 100,
  });

  // 真实调用函数
  await UserModel.deductCredits(user.id, 30);

  // 真实查询并断言结果
  const updated = await UserModel.findById(user.id);
  expect(updated.credits).toBe(70);  // 真实预期
});

// Services层 - Mock外部依赖，真实执行业务逻辑
test('应该正确更新机器状态', () => {
  const service = new MemoryStoreService();

  // 真实调用函数
  service.updateMachineStatus({
    id: 'machine-1',
    cpu_usage: 50,
  });

  // 真实查询并断言
  const machine = service.getMachine('machine-1');
  expect(machine.cpu_usage).toBe(50);
});

// Controllers层 - Mock Services，真实执行请求处理
test('登录成功应该返回token', async () => {
  // Mock: UserModel
  vi.mocked(UserModel.findByUsername).mockResolvedValue({
    id: 1,
    username: 'testuser',
    password: hashedPassword,
  });

  const app = await buildTestApp();

  // 真实: HTTP请求
  const response = await app.inject({
    method: 'POST',
    url: '/api/auth/login',
    payload: { username: 'testuser', password: 'password123' },
  });

  // 真实: 断言响应
  expect(response.statusCode).toBe(200);
  const result = JSON.parse(response.payload);
  expect(result.data.token).toBeTruthy();  // 真实生成的token
});
```

### 1.4 ❌ 错误示例

```typescript
// ❌ 错误1: Mock 被测函数
vi.spyOn(UserModel, 'deductCredits').mockResolvedValue({ credits: 70 });
// 这不是在测试 deductCredits，而是在测试 mock

// ❌ 错误2: 只断言调用，不验证结果
expect(mockDeductCredits).toHaveBeenCalledWith(1, 30);
// 没有验证实际结果

// ❌ 错误3: 测试专用代码
if (process.env.TEST_MODE) {
  return { success: true };
}
// 为了通过测试而修改代码

// ❌ 错误4: 跳过错误处理
test('应该处理错误', async () => {
  // 只测试成功场景，不测试失败场景
});
```

### 1.5 问题记录方法

```typescript
test.skip('Bug记录: 扣除点数余额未更新', async () => {
  // 问题记录
  const issue = `
  Bug报告: 扣除点数后余额未更新
  发现时间: 2024-12-25
  复现步骤:
    1. 创建用户，余额100
    2. 调用 deductCredits(userId, 30)
    3. 查询用户余额
  期望: 余额为70
  实际: 余额仍为100
  `;

  // 真实复现场景
  const user = await createTestUser({ credits: 100 });
  await UserModel.deductCredits(user.id, 30);
  const updated = await UserModel.findById(user.id);

  // 记录当前错误行为
  console.log('当前错误结果:', updated.credits);  // 100

  // 写下正确的预期 (修复后取消注释)
  // expect(updated.credits).toBe(70);
});
```

## 2. 测试分层策略

### 2.1 测试金字塔

```
                /\
               /  \
              / E2E \           ← 少量端到端测试
             /______\
            /        \
           / 集成测试  \        ← Routes层集成测试
          /__________\
         /            \
        /   单元测试    \     ← Models, Services, Controllers
       /________________\
```

### 2.2 各层职责

| 层级 | 职责 | 范围 | 数据真实性 |
|------|------|------|-----------|
| **Models** | 数据访问层 | CRUD、数据验证 | 真实数据库 (内存SQLite) |
| **Services** | 业务逻辑层 | 状态管理、业务规则 | 真实执行，Mock外部依赖 |
| **Controllers** | 请求处理层 | 参数验证、响应格式 | 真实执行，Mock Services |
| **Routes** | 集成层 | 完整请求流程 | 真实执行，少Mock |

### 2.3 测试执行顺序

```
Models (最独立)
   │
   ├── UserModel.test.ts ─────┐
   ├── SessionModel.test.ts ──┤
   └── MachineModel.test.ts ──┘
                    │
                    ▼
Services (依赖Models，Models可Mock)
   │
   ├── memory-store.service.test.ts ──┐
   └── session.service.test.ts ────────┤
                                        │
                                        ▼
Controllers (依赖Services，Services可Mock)
   │
   ├── auth.controller.test.ts ────────┐
   ├── session.controller.test.ts ─────┤
   └── user.controller.test.ts ────────┘
                                        │
                                        ▼
Routes (集成测试，验证完整流程)
   │
   ├── auth.routes.test.ts
   ├── session.routes.test.ts
   └── user.routes.test.ts
```

### 3.1 覆盖率目标

| 层级 | 行覆盖率 | 分支覆盖率 | 函数覆盖率 |

## 4. 测试命名规范

### 4.1 文件命名

```
src/tests/
├── unit/
│   ├── models/
│   │   ├── user.model.test.ts
│   │   ├── session.model.test.ts
│   │   └── machine.model.test.ts
│   ├── services/
│   │   ├── memory-store.service.test.ts
│   │   └── session.service.test.ts
│   └── controllers/
│       ├── auth.controller.test.ts
│       ├── session.controller.test.ts
│       └── user.controller.test.ts
└── integration/
    └── routes/
        ├── auth.routes.test.ts
        ├── session.routes.test.ts
        └── user.routes.test.ts
```

### 4.2 测试用例命名

| 模式 | 示例 | 说明 |
|------|------|------|
| `应该{预期行为}` | `应该正确扣除用户点数` | 描述预期结果 |
| `应该{预期}当{条件}` | `应该返回401当认证失败` | 描述条件下的预期 |
| `Bug记录:{问题描述}` | `Bug记录: 扣除点数余额未更新` | 记录已知Bug |
| `{场景}描述` | `余额不足时抛出错误` | 清晰描述测试场景 |

## 7. CI/CD集成

### 7.1 Git Hooks

使用 Husky + lint-staged，提交前自动运行相关测试：

```json
{
  "lint-staged": {
   "src/**/*.ts": [
     "vitest related --run"
   ]
  }
}
```

### 7.2 持续集成

```yaml
# .github/workflows/test.yml
name: Test
on: [push, pull_request]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - uses: actions/setup-node@v3
      - run: pnpm install
      - run: pnpm test
```
