# 安全漏洞测试用例设计报告

## 概述

本报告基于 Playwright 用户系统三端架构的代码分析，设计了全面的安全测试用例，涵盖认证授权、资源滥用、业务逻辑和数据安全四个主要类别。

## 一、认证与授权漏洞 (TIER-051 ~ TIER-055)

### TIER-051: API Key 复用漏洞

**漏洞类型**: 身份验证缺陷
**风险等级**: **High**

**漏洞描述**:
- API Key 没有过期机制
- 没有 IP 白名单限制
- 没有使用频率限制
- API Key 泄露后可被无限期使用

**攻击场景**:
攻击者获取到合法用户的 API Key 后，可以：
1. 冒充该用户创建会话
2. 消耗受害者的积分
3. 访问受害者的会话信息
4. 长期滥用（无过期时间）

**影响**:
- 用户积分被盗用
- 服务资源被滥用
- 无法追踪真实用户身份

**测试步骤**:
1. 创建两个测试用户（受害者和攻击者）
2. 攻击者窃取受害者的 API Key
3. 攻击者使用窃取的 API Key 创建会话
4. 验证积分从受害者账户扣除

**验证点**:
- **API 层**: 系统应拒绝没有 IP 限制的 API Key 请求
- **数据库层**: 会话应关联到受害者用户 ID
- **业务层**: 积分应从受害者账户扣除

**代码位置**:
- `/src/middlewares/auth.middleware.ts:46-72` (verifyApiKey)
- `/src/routes/session.routes.ts:20-32` (创建会话路由)

### TIER-052: 跨用户会话访问漏洞

**漏洞类型**: 访问控制缺陷
**风险等级**: **Critical**

**漏洞描述**:
- 用户可以通过枚举 Session ID 访问其他用户的会话
- 缺少会话归属检查

**攻击场景**:
1. 用户 A 枚举/猜测用户 B 的 Session ID
2. 用户 A 直接访问用户 B 的会话信息
3. 用户 A 可能获取敏感信息或控制用户 B 的会话

**影响**:
- 敏感信息泄露
- 会话劫持
- 跨用户攻击

**测试步骤**:
1. 创建用户 A 和用户 B
2. 用户 B 创建会话
3. 用户 A 尝试访问用户 B 的会话

**验证点**:
- **API 层**: 应返回 403 Forbidden
- **业务层**: 应检查 session.user_id === request.user.id

**代码位置**:
- `/src/controllers/session.controller.ts:92-135` (getSession)

**漏洞类型**: 权限提升
**风险等级**: **Critical**

**漏洞描述**:
- 普通用户可能通过某些方式访问管理员接口

1. 创建普通用户

3. 尝试访问 `/api/admin/users` 等管理员端点

**验证点**:
- **API 层**: 应返回 403 Forbidden
- **中间件层**: verifyAdmin 应正确检查 role

**代码位置**:

### TIER-054: JWT Token 过期后仍可用漏洞

**漏洞类型**: 会话管理缺陷
**风险等级**: **Medium**

**漏洞描述**:
- Token 过期检查可能不严格
- 允许使用过期的 Token 访问资源

**攻击场景**:
1. 攻击者获取过期的 JWT Token
2. 修改系统时间或绕过过期检查
3. 使用过期 Token 访问受保护资源

**影响**:
- 未授权访问
- 会话固定攻击

**测试步骤**:
1. 创建测试用户
2. 生成已过期的 JWT Token (expiresIn: '-1h')
3. 使用过期 Token 访问受保护端点

**验证点**:
- **API 层**: 应返回 401 Unauthorized
- **工具层**: jwt.verify 应正确检测过期

**代码位置**:
- `/src/utils/auth.ts:49-58` (verifyToken)
- `/src/middlewares/auth.middleware.ts:8-44` (verifyJWT)

**测试步骤**:

3. 检查是否有重复或可预测模式

**验证点**:
- **安全层**: Session ID 应符合 UUID v4 格式
- **安全层**: 所有 Session ID 应唯一

**代码位置**:

## 二、资源滥用漏洞 (TIER-061 ~ TIER-065)

### TIER-061: 超出并发限制漏洞

**漏洞类型**: 资源耗尽
**风险等级**: **High**

**漏洞描述**:
- 没有限制单个用户可创建的并发会话数
- 用户可以创建大量会话耗尽系统资源

**攻击场景**:
1. 攻击者创建大量会话
2. 占用所有可用的机器实例
3. 导致合法用户无法创建会话（拒绝服务）

**影响**:
- 资源耗尽
- 拒绝服务
- 系统崩溃

**测试步骤**:
1. 创建测试用户（积分充足）
2. 批量创建会话（尝试创建 100 个）
3. 验证系统是否有并发限制

**验证点**:
- **API 层**: 应限制单个用户的并发会话数（如 50 个）
- **数据库层**: 检查实际创建的会话数
- **业务层**: 应返回配额超限错误

**代码位置**:
- `/src/services/session.service.ts:16-132` (createBrowserSession)
- `/src/models/machine.model.ts:186-237` (findAvailable)

### TIER-062: 积分扣费竞态条件漏洞

**漏洞类型**: 竞态条件
**风险等级**: **Critical**

**漏洞描述**:
- 并发创建会话时，积分检查和扣费之间存在竞态条件
- 可能导致重复扣费或漏扣费

**攻击场景**:
1. 用户积分只有 1 点
2. 同时发送 5 个创建会话请求
3. 如果存在竞态条件，可能创建多个会话（只扣 1 次费）

**影响**:
- 积分系统绕过
- 资源滥用
- 收入损失

**测试步骤**:
1. 将用户积分设置为 1
2. 并发发送 5 个创建会话请求
3. 检查实际创建的会话数和扣费情况

**验证点**:
- **业务层**: 只应创建 1 个会话
- **数据库层**: 用户积分应 >= 0
- **一致性**: 积分扣费与会话创建应原子化

**代码位置**:
- `/src/services/session.service.ts:27-30` (积分检查)
- `/src/models/user.model.ts:130-144` (deductCredits)

## 三、业务逻辑漏洞 (TIER-041 ~ TIER-045)

### TIER-041: 并发释放会话竞态条件

**漏洞类型**: 竞态条件
**风险等级**: **High**

**漏洞描述**:
- 多次并发调用释放会话可能导致重复扣费
- markDisconnected 方法的幂等性可能不足

**攻击场景**:
1. 用户创建一个会话（运行 2 分钟）
2. 同时发送 5 个释放会话请求
3. 如果存在竞态条件，可能扣费 5 次（共 10 点）

**影响**:
- 重复扣费
- 用户投诉

**测试步骤**:
1. 创建会话（运行 2 分钟）
2. 并发发送 5 个释放请求
3. 检查最终扣费情况

**验证点**:
- **业务层**: 应只扣费 1 次（2 点）
- **幂等性**: markDisconnected 应保证幂等

**代码位置**:
- `/src/models/session.model.ts:198-295` (markDisconnected - 包含幂等性逻辑)

**测试步骤**:
1. 创建会话并设置为 connected
2. 手动将状态改为 disconnected
3. 尝试再次释放会话

**验证点**:
- **API 层**: 应返回会话已释放
- **数据库层**: 积分不应重复扣除

**代码位置**:
- `/src/controllers/session.controller.ts:164-269` (releaseSession)

### TIER-043: 时间窗口利用漏洞

**漏洞类型**: 计费逻辑缺陷
**风险等级**: **Low**

**漏洞描述**:

1. 创建运行 59 秒的会话
2. 等待 1 秒（达到 60 秒）
3. 释放会话并检查扣费

**验证点**:
- **业务层**: 60 秒应扣 1 点
- **计费逻辑**: 应正确向上取整

**代码位置**:
- `/src/models/session.model.ts:229-230` (credits_used 计算)

**风险等级**: **Medium**

**验证点**:

## 五、测试执行指南

### 环境准备

1. 启动测试环境：
```bash
pnpm dev:minimal
```

2. 准备测试数据库：
```bash
NODE_ENV=test pnpm migrate
```

### 运行测试

```bash
# 运行所有安全测试
npx playwright test tests/e2e/security-vulnerabilities.spec.ts

# 运行特定类别的测试
npx playwright test tests/e2e/security-vulnerabilities.spec.ts -g "认证与授权漏洞"
npx playwright test tests/e2e/security-vulnerabilities.spec.ts -g "资源滥用漏洞"
npx playwright test tests/e2e/security-vulnerabilities.spec.ts -g "业务逻辑漏洞"
npx playwright test tests/e2e/security-vulnerabilities.spec.ts -g "数据安全漏洞"

# 运行特定测试用例
npx playwright test tests/e2e/security-vulnerabilities.spec.ts -g "TIER-051"
```

### 清理测试数据

测试完成后，测试用例会自动清理创建的数据。如果需要手动清理：

```sql
-- 删除测试用户（用户名以 test_ 开头）
DELETE FROM sessions WHERE user_id IN (SELECT id FROM users WHERE username LIKE 'test_%');
DELETE FROM credit_history WHERE user_id IN (SELECT id FROM users WHERE username LIKE 'test_%');
DELETE FROM users WHERE username LIKE 'test_%';
```

## 六、漏洞修复优先级

### Critical (立即修复)
- TIER-052: 跨用户会话访问漏洞
- TIER-053: 管理员权限绕过漏洞
- TIER-062: 积分扣费竞态条件漏洞
- TIER-071: 越权访问他人会话漏洞
- TIER-074: SQL 注入尝试漏洞

### High (优先修复)
- TIER-051: API Key 复用漏洞
- TIER-061: 超出并发限制漏洞
- TIER-063: 负数积分漏洞
- TIER-064: 无限会话创建漏洞
- TIER-041: 并发释放会话竞态条件
- TIER-075: 会话劫持漏洞

### Medium (计划修复)
- TIER-054: JWT Token 过期后仍可用漏洞
- TIER-055: 会话固定攻击漏洞
- TIER-065: 机器资源耗尽漏洞
- TIER-042: 会话状态不一致漏洞
- TIER-044: 积分历史记录不一致漏洞
- TIER-045: 机器实例计数不一致漏洞
- TIER-072: 越权访问他人积分信息漏洞
- TIER-073: 敏感信息泄露漏洞

### Low (后续优化)
- TIER-043: 时间窗口利用漏洞

## 七、安全加固建议

### 1. 认证与授权
- 实施 API Key 过期机制
- 添加 IP 白名单功能
- 实施请求频率限制
- 加强会话归属检查

### 2. 资源管理
- 添加用户并发会话数限制
- 实施积分扣除的原子操作
- 添加请求队列防止竞态条件

### 3. 数据安全
- 过滤 API 响应中的敏感信息
- 实施严格的访问控制
- 添加审计日志

### 4. 监控与告警
- 监控异常的会话创建行为
- 监控积分异常变动
- 设置资源使用告警
