# 智能测试环境说明

## 功能特性

✅ **动态端口分配** - 测试时自动分配可用端口，避免占用固定端口
✅ **自动服务启动** - 测试前自动启动管理端 + 多个机器服务
✅ **自动清理** - 测试结束后自动关闭所有服务
✅ **灵活配置** - 可自定义机器数量

---

## 使用方式

### 1️⃣ 平时开发（固定端口）

```bash
# 启动管理端（端口 3000）
pnpm dev

# 启动机器服务（gRPC 50052, 代理 8082）
pnpm dev:machine
```

### 2️⃣ 运行 E2E 测试（动态端口）

```bash
# 默认启动 2 个机器
pnpm test:e2e

# 启动 3 个机器
pnpm test:e2e:3

# 启动 5 个机器
pnpm test:e2e:5

# 只运行 P0 测试
pnpm test:e2e:p0

# 只运行 P1 测试
pnpm test:e2e:p1

# 运行特定测试文件
npx playwright test tests/e2e/p0-critical.spec.ts -g "P0-L01"
```

### 3️⃣ 自定义机器数量

```bash
# 通过环境变量设置
TEST_MACHINE_COUNT=10 pnpm test:e2e

# 或使用脚本
./scripts/test-e2e.sh 3
```

## 工作原理

### 测试启动流程

```
1. globalSetup 触发
   ↓
2. 分配随机端口
   - 管理端 HTTP: 随机 (如 54321)
   - 管理端 gRPC: 随机 (如 54322)
   - 机器 1 gRPC: 随机 (如 54323)
   - 机器 1 代理: 随机 (如 54324)
   - 机器 2 gRPC: 随机 (如 54325)
   - 机器 2 代理: 随机 (如 54326)
   ↓
3. 启动管理服务器
   - 等待 /health 端点就绪
   ↓
4. 并行启动所有机器服务
   - 等待注册到管理端
   ↓
5. 设置环境变量
   - BASE_URL
   - MANAGER_GRPC_URL
   ↓
6. 运行测试
   ↓
7. globalTeardown 触发
   - 停止所有服务
   - 清理进程
```

### 架构示意

```
测试环境 (动态端口)
├── 管理服务器 (localhost:54321)
│   ├── HTTP API
│   └── gRPC Server (localhost:54322)
│
├── 机器服务 1 (localhost:54323)
│   ├── gRPC Client
│   └── Proxy Server (localhost:54324)
│
└── 机器服务 2 (localhost:54325)
    ├── gRPC Client
    └── Proxy Server (localhost:54326)
```

## 故障排查

### Q: 测试启动失败？
**A**: 检查是否有端口冲突
```bash
# 查看占用端口的进程
lsof -i :3000
lsof -i :50051
lsof -i :50052

# 关闭占用端口的进程
kill -9 <PID>
```

### Q: 机器服务没有注册成功？
**A**: 查看日志文件
```bash
# 查看管理服务器日志
cat logs/test-logs/manager-*.log

# 查看机器服务日志
cat logs/test-logs/machine-*.log
```

### Q: 想在测试中禁用自动启动？
**A**: 修改 `playwright.global.ts`，注释掉启动代码

## 环境变量

| 变量 | 说明 | 默认值 |
|-----|------|--------|
| `TEST_MACHINE_COUNT` | 启动的机器数量 | `2` |
| `BASE_URL` | 管理端 URL（自动设置） | - |
| `MANAGER_GRPC_URL` | gRPC 地址（自动设置） | - |
| `NODE_ENV` | 测试模式 | `test` |
