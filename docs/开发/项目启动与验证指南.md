## 1. 项目概述

### 1.1 系统架构

本项目是一个分布式 Playwright 浏览器管理系统，包含三个主要组件：

```
┌─────────────────────────────────────────────────────────────┐
│                    Playwright 用户管理系统                    │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  ┌──────────────────┐         ┌──────────────────┐         │
│  │  Management      │  gRPC   │   Machine        │         │
│  │  Server          │ ◄────► │   Service        │         │
│  │  (管理端)         │         │   (机器端)        │         │
│  │                  │         │                  │         │
│  │  - HTTP API      │         │  - Browser       │         │
│  │  - gRPC Server   │         │  - Proxy Server  │         │
│  │  - 用户管理      │         │  - Playwright    │         │
│  │  - 点数计费      │         │                  │         │
│  └──────────────────┘         └──────────────────┘         │
│         ▲                                    ▲              │
│         │                                    │              │
│         └──────────────┬─────────────────────┘              │
│                        │                                    │
│                 ┌──────┴──────┐                             │
│                 │   Client    │                             │
│                 │    SDK      │                             │
│                 └─────────────┘                             │
└─────────────────────────────────────────────────────────────┘
```

### 1.2 组件说明

| 组件 | 入口文件 | 端口 | 说明 |
|------|---------|------|------|
| Management Server | `src/manager/server.ts` | HTTP: 3000, gRPC: 50051 | 提供用户管理、会话分配、点数计费 |
| Machine Service | `src/machine/server.ts` | gRPC: 50052, Proxy: 8082 | 运行浏览器实例，处理 WebSocket 代理 |
| Client SDK | `src/sdk/client.ts` | - | 用户客户端 SDK |

### 1.3 目录结构

```
playwright-user-sys/
├── src/
│   ├── shared/          # 共享代码（types, utils, protos）
│   ├── manager/         # 管理端代码
│   │   ├── app.ts       # 管理端应用构建和启动逻辑
│   │   └── server.ts    # 管理端入口
│   ├── machine/         # 机器端代码
│   │   ├── app.ts       # 机器端应用逻辑
│   │   └── server.ts    # 机器端入口
│   ├── models/          # 数据库模型
│   ├── controllers/     # API 控制器
│   ├── services/        # 业务逻辑服务
│   ├── routes/          # 路由定义
│   └── config/          # 配置文件
├── scripts/             # 工具脚本
├── migrations/          # 数据库迁移
├── tests/               # 测试文件
├── docs/                # 文档
└── data/                # 数据目录（SQLite 数据库、上传文件等）
```

## 2. 前置条件

### 2.1 系统要求

| 项目 | 最低版本 | 推荐版本 | 说明 |
|------|---------|---------|------|
| Node.js | 18.x | 20.x | 需要支持 ES2022+ |

## 3. 环境配置

### 3.1 环境变量文件

项目包含多个环境变量配置文件：

| 文件 | 用途 |
|------|------|
| `.env.example` | 环境变量模板 |
| `.env.dev` | 开发环境配置 |
| `.env` | 当前环境配置（需自行创建） |
| `.env.machine.example` | 机器端配置模板 |

### 3.2 创建配置文件

#### 3.2.1 管理端配置

```bash
# 复制示例配置
cp .env.example .env

# 编辑配置文件
vim .env  # 或使用你喜欢的编辑器
```

**最小配置示例**:

```env
# 服务器配置
PORT=3000
HOST=localhost
NODE_ENV=development

# 数据库配置（开发环境使用 SQLite）
DB_TYPE=sqlite
DB_NAME=playwright_user_sys
DB_PATH=./data/db.sqlite

# JWT 配置
JWT_SECRET=your-secret-key-change-in-production
JWT_EXPIRES_IN=1d

# 管理员初始账号
ADMIN_USERNAME=admin
ADMIN_PASSWORD=REDACTED_ADMIN_PASS

# 实例配置
INSTANCE_TIMEOUT=60000

# gRPC 服务器配置
GRPC_PORT=50051
```

**生产环境 MySQL 配置示例**:

```env
# 数据库配置
DB_TYPE=mysql
DB_NAME=playwright_user_sys
DB_HOST=localhost
DB_PORT=3306
DB_USER=root
DB_PASSWORD=your-password
```

#### 3.2.2 机器端配置

```bash
# 复制机器端配置模板
cp .env.machine.example .env.machine
```

**机器端配置示例**:

```env
NODE_ENV=development
MACHINE_ID=machine-1
MACHINE_NAME=local-machine

# 管理端连接
MANAGER_HOST=localhost:50051

# 端口配置
MACHINE_GRPC_PORT=50052
PROXY_PORT=8082

# 浏览器配置
MAX_SESSIONS=10
SESSION_TIMEOUT=300000
```

### 3.3 环境变量说明

#### 3.3.1 通用配置

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `NODE_ENV` | development | 运行环境: development/production/test |
| `PORT` | 3000 | HTTP 服务端口 |
| `HOST` | localhost | 服务主机名 |

#### 3.3.2 数据库配置

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `DB_TYPE` | sqlite | 数据库类型: sqlite/mysql |
| `DB_NAME` | playwright_user_sys | 数据库名称 |
| `DB_PATH` | ./data/db.sqlite | SQLite 文件路径 |
| `DB_HOST` | localhost | MySQL 主机 |
| `DB_PORT` | 3306 | MySQL 端口 |
| `DB_USER` | root | MySQL 用户名 |
| `DB_PASSWORD` | - | MySQL 密码 |

#### 3.3.3 安全配置

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `JWT_SECRET` | - | JWT 签名密钥（必须修改） |
| `JWT_EXPIRES_IN` | 1d | Token 过期时间 |
| `ADMIN_USERNAME` | admin | 管理员用户名 |
| `ADMIN_PASSWORD` | REDACTED_ADMIN_PASS | 管理员密码 |

#### 3.3.4 服务配置

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `GRPC_PORT` | 50051 | gRPC 服务端口 |
| `PROXY_PORT` | 8081 | 代理服务端口 |
| `INSTANCE_TIMEOUT` | 60000 | 实例超时时间（毫秒） |
| `MACHINE_MONITOR_INTERVAL` | 30000 | 机器监控间隔（毫秒） |

## 4. 依赖安装

### 4.1 安装项目依赖

```bash
# 使用 pnpm 安装依赖
pnpm install

# 安装过程会自动执行以下操作：
# 1. 下载所有依赖包
# 2. 运行 setup-aliases.sh 脚本设置路径映射
# 3. 创建 node_modules 中的软链接
```

### 4.2 路径映射设置

项目使用 TypeScript 路径映射（`@shared/*`, `@manager/*`, `@machine/*`），需要设置软链接：

```bash
# 手动运行路径映射脚本
pnpm setup:aliases

# 或
bash scripts/setup-aliases.sh
```

**脚本功能**:
- 读取 `tsconfig.json` 中的 `paths` 配置
- 在 `node_modules` 中创建对应的软链接
- 使得 tsx 可以正确解析 `@shared/*` 等导入

**验证路径映射**:

```bash
# 检查软链接是否创建成功
ls -la node_modules/@shared
ls -la node_modules/@manager
ls -la node_modules/@machine

# 应该看到指向 src/shared 等目录的软链接
```

### 4.3 验证安装

```bash
# 检查 TypeScript 编译
pnpm build

# 预期输出:
# ✅ 编译成功（可能有一些类型警告，这是正常的）

# 检查依赖是否完整
pnpm list --depth=0
```

## 5. 数据库配置

### 5.1 数据库初始化

#### 5.1.1 自动初始化（推荐）

管理端启动时会自动运行数据库迁移：

```bash
# 启动管理端，自动初始化数据库
pnpm dev:server
```

**自动执行的操作**:
1. 创建数据库表（users, machines, sessions 等）
2. 创建管理员账号
3. 重置所有机器状态为离线

#### 5.1.2 手动初始化

```bash
# 运行数据库迁移
pnpm migrate
```

**创建的数据表**:

| 表名 | 说明 |
|------|------|
| users | 用户表 |
| machines | 机器表 |
| sessions | 会话表 |
| operation_logs | 操作日志表 |
| request_logs | 请求日志表 |
| webhook_events | Webhook 事件表 |

### 5.2 创建测试用户

```bash
# 创建测试用户
pnpm create-test-user
```

**测试用户信息**:
- 用户名: `test_user`
- 密码: `test_password`
- 初始点数: 100
- 脚本会输出 API Key

### 5.3 数据库迁移文件

如需修改数据库结构，可以创建迁移文件：

```bash
# 查看现有迁移
ls migrations/

# 运行特定迁移
pnpm migrate:proxy-port
```

### 5.4 数据库配置验证


### 6.3 进程管理

#### 6.3.1 使用 PM2（推荐）

```bash
# 安装 PM2
pnpm add -g pm2

# 启动管理端
pm2 start dist/manager/server.js --name playwright-manager

# 启动机器端
pm2 start dist/machine/server.js --name playwright-machine

# 查看状态
pm2 status

# 查看日志
pm2 logs playwright-manager
pm2 logs playwright-machine

# 停止服务
pm2 stop playwright-manager
pm2 stop playwright-machine

# 重启服务
pm2 restart playwright-manager
pm2 restart playwright-machine
```

#### 6.3.2 PM2 配置文件

创建 `ecosystem.config.js`:

```javascript
module.exports = {
  apps: [
    {
      name: 'playwright-manager',
      script: './dist/manager/server.js',
      instances: 1,
      exec_mode: 'fork',
      env: {
        NODE_ENV: 'production',
      },
      error_file: './logs/manager-error.log',
      out_file: './logs/manager-out.log',
      log_date_format: 'YYYY-MM-DD HH:mm:ss',
    },
    {
      name: 'playwright-machine',
      script: './dist/machine/server.js',
      instances: 1,
      exec_mode: 'fork',
      env: {
        NODE_ENV: 'production',
      },
      error_file: './logs/machine-error.log',
      out_file: './logs/machine-out.log',
      log_date_format: 'YYYY-MM-DD HH:mm:ss',
    },
  ],
};
```

使用配置文件启动:

```bash
pm2 start ecosystem.config.js
```

## 9. 开发模式 vs 生产模式

### 9.1 模式对比

| 特性 | 开发模式 | 生产模式 |
|------|---------|----------|
| 启动命令 | `pnpm dev` | `pnpm start` |
| 入口文件 | `src/manager/server.ts` | `dist/manager/server.js` |
| 运行工具 | tsx watch | Node.js |
| 热重载 | ✅ 支持 | ❌ 不支持 |
| 日志级别 | debug | info |
| 数据库 | SQLite | MySQL 推荐 |
| 错误处理 | 详细堆栈 | 简洁日志 |

### 9.2 开发模式特性

#### 9.2.1 热重载

```bash
# 使用 tsx watch 启动
pnpm dev

# 修改代码后自动重启
# - 保存文件后自动检测变化
# - 自动重新编译和重启服务
# - 控制台显示重启日志
```

#### 9.2.2 详细日志

开发模式下会显示：

- 详细的错误堆栈
- SQL 查询日志
- gRPC 通信日志
- 请求/响应详情

### 9.3 生产模式特性

#### 9.3.1 性能优化

- 使用编译后的 JavaScript
- 移除调试代码
- 优化日志输出

## 10. 常见问题排查

### 10.1 启动问题

#### 问题 1: 端口被占用

**症状**:
```
Error: listen EADDRINUSE: address already in use :::3000
```

**解决方案**:

```bash
# 查找占用端口的进程
lsof -i :3000

# 终止进程
kill -9 <PID>

# 或修改 .env 中的端口配置
PORT=3001
```

#### 问题 2: 模块导入失败

**症状**:
```
Error: Cannot find module '@shared/utils/logger'
```

**解决方案**:

```bash
# 重新运行路径映射脚本
pnpm setup:aliases

# 检查软链接
ls -la node_modules/@shared

# 如果还不行，重新安装依赖
rm -rf node_modules
pnpm install
```

#### 问题 3: 数据库连接失败

**症状**:
```
Error: connect ECONNREFUSED /var/run/mysql.sock
```

**解决方案**:

```bash
# 检查 MySQL 服务状态
# macOS
brew services list
brew services start mysql

# Linux
sudo systemctl status mysql
sudo systemctl start mysql

# 或切换到 SQLite
# 修改 .env
DB_TYPE=sqlite
DB_PATH=./data/db.sqlite
```

#### 问题 4: TypeScript 编译错误

**症状**:
```
error TS2307: Cannot find module '...'
```

**解决方案**:

```bash
# 清理并重新构建
rm -rf dist
pnpm build

# 检查 tsconfig.json 路径配置
cat tsconfig.json | grep paths

# 如果是类型错误，可以使用宽松模式
# package.json 中已配置: "noImplicitAny": false
```

### 10.2 运行时问题

#### 问题 1: gRPC 连接失败

**症状**:
```
Error: UNAVAILABLE: Connection dropped
```

**解决方案**:

```bash
# 检查管理端是否先启动
ps aux | grep "node.*manager"

# 检查 gRPC 端口
lsof -i :50051

# 检查机器端配置
cat .env.machine | grep MANAGER_HOST

# 确认连接配置正确
MANAGER_HOST=localhost:50051  # 不是 http://localhost:50051
```

#### 问题 2: 会话创建失败

**症状**:
```
Error: No available machines
```

**解决方案**:

```bash
# 1. 检查机器是否在线
curl http://localhost:3000/api/machines \
  -H "Authorization: Bearer $ADMIN_TOKEN"

# 2. 检查机器日志中的错误
pnpm dev:machine

# 3. 重启机器端
# 停止当前机器端进程
# 重新启动 pnpm dev:machine
```

#### 问题 3: JWT Token 无效

**症状**:
```
Error: Invalid token
```

**解决方案**:

```bash
# 1. 检查 JWT_SECRET 配置
cat .env | grep JWT_SECRET

# 2. 重新登录获取新 token
curl -X POST http://localhost:3000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username": "admin", "password": "REDACTED_ADMIN_PASS"}'

# 3. 确认 token 格式正确
Authorization: Bearer <token>
```

## 11. Docker 部署

### 11.1 Docker Compose 快速启动

#### 11.1.1 仅启动管理端

```bash
# 使用默认 docker-compose.yml
docker-compose up -d

# 查看日志
docker-compose logs -f manager

# 停止服务
docker-compose down
```

#### 11.1.2 启动完整系统（管理端 + 机器端）

```bash
# 使用完整配置
docker-compose -f docker-compose.full.yml up -d

# 查看服务状态
docker-compose -f docker-compose.full.yml ps

# 查看日志
docker-compose -f docker-compose.full.yml logs -f
```

### 11.2 手动 Docker 部署

#### 11.2.1 构建镜像

```bash
# 构建管理端镜像
docker build -f Dockerfile -t playwright-manager:latest .

# 构建机器端镜像
docker build -f Dockerfile.machine -t playwright-machine:latest .
```

#### 11.2.2 启动管理端容器

```bash
docker run -d \
  --name playwright-manager \
  -p 3000:3000 \
  -p 50051:50051 \
  -v $(pwd)/data:/app/data \
  -e NODE_ENV=production \
  -e DB_TYPE=sqlite \
  -e DB_PATH=/app/data/db.sqlite \
  playwright-manager:latest
```

#### 11.2.3 启动机器端容器

```bash
docker run -d \
  --name playwright-machine \
  -p 8082:8082 \
  -p 50052:50052 \
  -v /path/to/chrome:/opt/chrome:ro \
  -e MANAGER_HOST=host.docker.internal:50051 \
  -e MACHINE_ID=docker-machine-1 \
  playwright-machine:latest
```

### 11.3 Docker 验证

```bash
# 检查容器状态
docker ps

# 检查容器日志
docker logs playwright-manager
docker logs playwright-machine

# 进入容器调试
docker exec -it playwright-manager sh
docker exec -it playwright-machine sh
```
