## 1. 重构背景

### 1.1 当前问题

项目采用分布式架构，包含管理端和机器端两个独立服务：

- **管理端 (`src/app.ts`)**: 提供 HTTP API，同时启动 gRPC 服务接收机器连接
- **机器端 (`src/machine/index.ts`)**: 运行浏览器实例，通过 gRPC 连接管理端

**当前架构存在的问题：**

1. **入口混乱**: `src/app.ts` 同时承担管理端 API 和接收机器连接的职责
2. **目录结构不清**: `src/machine/` 既是机器端的代码，又被管理端依赖
3. **共享代码混乱**: proto 文件、类型定义、工具函数分散在各处
4. **部署不明确**: 难以区分哪些代码属于管理端，哪些属于机器端

### 1.2 重构目标

1. **清晰的目录结构**: 管理端和机器端代码完全分离
2. **独立的入口文件**: 两边都有各自的 `app.ts` 和 `server.ts`
3. **共享代码提取**: 公共代码统一放在 `shared/` 目录
4. **路径别名优化**: 使用 `@shared` 别名引用共享代码
5. **部署友好**: 可以独立打包和部署管理端、机器端

### 1.3 TypeScript 路径映射配置

项目已配置 `tsconfig.json` 路径映射，支持使用 `@` 别名：

```json
{
  "compilerOptions": {
    "baseUrl": ".",
    "paths": {
      "@/*": ["src/*"],
      "@shared/*": ["src/shared/*"],
      "@manager/*": ["src/manager/*"],
      "@machine/*": ["src/machine/*"]
    }
  }
}
```

#### 路径别名对照表

| 别名 | 映射路径 | 使用场景 | 示例 |
|------|----------|----------|------|
| `@shared/*` | `src/shared/*` | 引用共享代码 | `import { logger } from '@shared/utils/logger.js'` |
| `@manager/*` | `src/manager/*` | 管理端内部引用 | `import { buildManager } from '@manager/app.js'` |
| `@machine/*` | `src/machine/*` | 机器端内部引用 | `import { CONFIG } from '@machine/config.js'` |
| `@/*` | `src/*` | 通用引用 | `import { UserModel } from '@/models/user.model.js'` |

#### 重构前后 import 对比

| 场景 | 重构前 | 重构后 |
|------|--------|--------|
| 管理端引用 logger | `import { logger } from '../utils/logger.js'` | `import { logger } from '@shared/utils/logger.js'` |
| 机器端引用 proto | `import { proto } from '../protos/machine_service.proto'` | `import { proto } from '@shared/protos/machine_service.proto'` |
| 管理端引用模型 | `import { UserModel } from '../models/user.model.js'` | `import { UserModel } from '@/models/user.model.js'` |

## 2. 总体策略

### 2.1 重构原则

| 原则 | 说明 |
|------|------|
| **渐进式** | 分步骤进行，每步独立验证 |
| **可回滚** | 每步都有明确的回滚方法 |
| **向后兼容** | 保留原有入口，确保平滑过渡 |
| **测试先行** | 先写测试验证脚本，再执行重构 |

### 2.3 测试执行规范

每一步骤都必须执行以下测试，并在步骤文档末尾记录测试结果：

#### 测试前基线 (重构前执行)

```bash
# 记录基线测试结果
echo "=== 步骤 N 基线测试 ===" >> tests/baseline-stepN.log
date >> tests/baseline-stepN.log

# 单元测试基线
pnpm test:unit 2>&1 | tee -a tests/baseline-stepN.log

# API 测试基线 (需要服务运行)
# pnpm test:api 2>&1 | tee -a tests/baseline-stepN.log
```

#### 重构后验证 (重构后执行)

```bash
# 1. 步骤专用验证脚本
node tests/verify-stepN-[name].js

# 2. 单元测试回归
pnpm test:unit

# 3. API 功能测试 (如适用)
pnpm test:api
pnpm test:login

# 4. TypeScript 编译检查
pnpm build
```

```

  │
  ├─ 创建 src/machine/app.ts

  │
  ├─ 修改 package.json scripts

  │

## 5. 验证策略

```
改造 → 独立验证 → 回归测试 → (通过后)继续 → (失败则)回滚

### 5.2 验证类型

| 类型 | 描述 | 工具 |
|------|------|------|
| **结构验证** | 检查文件、目录是否正确创建 | Node.js assert |
| **启动验证** | 检查服务能否正常启动 | spawn + 日志检查 |
| **功能验证** | 检查核心功能是否正常 | API 测试 |
| **集成验证** | 检查服务间通信是否正常 | 端到端测试 |

## 6. 回滚策略

### 6.1 分支策略

```bash
# 创建重构分支
git checkout -b refactor/manager-machine-separation

# 每完成一步，提交一次
git add . && git commit -m "Step 1: Create shared directory"

# 如果某步失败，回滚到上一步
git reset --hard HEAD~1

# 如果全部失败，回到主分支
git checkout main
```

| 步骤 | 回滚命令 |

| 步骤3 | `rm src/machine/app.ts && rm src/machine/server.ts && git checkout src/machine/index.ts` |
| 步骤4 | `git checkout package.json` |
| 步骤5 | `git reset --hard HEAD~1` |
