## 1. 回滚原则

### 1.1 何时回滚

```
┌─────────────────────────────────────────────────────────────────┐
│                    回滚决策流程                                  │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  执行验证测试                                                    │
│     │                                                           │
│     ├── 全部通过 → Git 提交，继续下一步                          │
│     │                                                           │
│     └── 有失败                                                  │
│         │                                                       │
│         ├── 问题可快速修复 (< 10分钟) → 修复后重新验证           │
│         │                                                       │
│         └── 问题复杂或时间不足 → 执行回滚                        │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 1.2 回滚触发条件

| 条件 | 严重程度 | 操作 |
|------|----------|------|
| TypeScript 编译错误 | 高 | 立即回滚 |
| 服务无法启动 | 高 | 立即回滚 |
| 核心功能失效 | 高 | 立即回滚 |
| 非关键警告 | 低 | 记录，不回滚 |
| 测试套件个别失败 | 中 | 评估后决定 |

## 2. 步骤级回滚方案

### 2.1 步骤 1 回滚：共享代码目录

**触发条件**:
- TypeScript 编译失败
- 模块导入错误无法修复
- 共享代码访问失败

**回滚命令**:

```bash
# 1. 删除创建的 shared 目录
rm -rf src/shared

# 2. 恢复原有文件结构
git checkout src/protos
git checkout src/types
git checkout src/utils/logger.ts

# 3. 恢复所有导入路径
# 使用 sed 批量替换回来
find src -name "*.ts" -type f -exec sed -i '' "s|from '@shared/protos/|from '../protos/|g" {} \;
find src -name "*.ts" -type f -exec sed -i '' "s|from '@shared/types/|from '../types/|g" {} \;
find src -name "*.ts" -type f -exec sed -i '' "s|from '@shared/utils/logger'|from '../utils/logger'|g" {} \;

# 4. 恢复 tsconfig.json（如果修改过）
git checkout tsconfig.json

# 5. 验证回滚
pnpm build
```

**验证回滚成功**:
```bash
# 确认原有结构恢复
ls -la src/protos
ls -la src/types
ls -la src/utils/logger.ts

# 确认 shared 目录已删除
! [ -d src/shared ] && echo "回滚成功" || echo "回滚失败"
```

### 2.2 步骤 2 回滚：管理端入口

**触发条件**:
- 管理端无法启动
- API 测试失败
- 验证脚本关键测试失败

**回滚命令**:

```bash
# 1. 删除创建的 manager 目录
rm -rf src/manager

# 2. 恢复原有的 server.ts
git checkout src/server.ts

# 3. 删除验证脚本
rm tests/verify-step2-manager.js

# 4. 验证回滚
pnpm build
timeout 10 pnpm dev
```

**验证回滚成功**:
```bash
# 确认原有入口可用
grep -q "function start()" src/server.ts && echo "回滚成功"

# 确认 manager 目录已删除
! [ -d src/manager ] && echo "清理成功" || echo "清理失败"
```

### 2.4 步骤 4 回滚：配置和脚本

**触发条件**:
- 新脚本无法使用
- 启动路径错误
- 验证脚本失败

**回滚命令**:

```bash
# 1. 恢复 package.json
git checkout package.json

# 2. 验证回滚
pnpm run --help | grep -E "dev:server|dev:machine"
# 应该看不到新脚本，或者看到旧脚本
```

**验证回滚成功**:
```bash
# 确认原有脚本可用
pnpm dev --help 2>&1 | head -5
```

### 2.5 步骤 5 回滚：集成测试

**触发条件**:
- 集成测试多处失败
- 整体架构问题
- 无法通过任何验证

**回滚命令**:

```bash
# 完整回滚到重构前状态
git log --oneline -10
# 找到重构前的 commit hash
git checkout <重构前的commit-hash>

# 或者使用回滚标签（如果有）
git checkout before-refactor

# 验证回滚
pnpm build
pnpm dev
```

## 3. 完整回滚方案

### 3.1 回滚所有更改

```bash
#!/bin/bash
# 完整回滚脚本

echo "=== 开始完整回滚 ==="

# 1. 检查当前状态
echo "当前分支: $(git branch --show-current)"
echo "当前 commit: $(git rev-parse --short HEAD)"

# 2. 回滚所有文件
echo "回滚文件..."
rm -rf src/shared
rm -rf src/manager
rm -f src/machine/app.ts
rm -f src/machine/server.ts
git checkout src/protos
git checkout src/types
git checkout src/utils/logger.ts
git checkout src/server.ts
git checkout src/machine/index.ts
git checkout tsconfig.json
git checkout package.json

# 3. 删除验证脚本
echo "删除验证脚本..."
rm -f tests/verify-step*.js

# 4. 验证回滚
echo "验证回滚..."
pnpm build
if [ $? -eq 0 ]; then
  echo "✅ 回滚成功"
else
  echo "❌ 回滚后编译失败，请手动检查"
fi

echo "=== 回滚完成 ==="
```

### 3.2 Git 回滚

```bash
# 方法 1: 回滚到指定 commit
git log --oneline -10
git reset --hard <commit-hash>

# 方法 2: 创建回滚 commit
git revert <commit-range>

# 方法 3: 使用回滚分支
git checkout -b rollback-branch
git reset --hard <stable-commit-hash>
```

## 6. 紧急回滚

### 6.1 一键回滚脚本

创建 `scripts/rollback-refactor.sh`:

```bash
#!/bin/bash
set -e

echo "=== 紧急回滚脚本 ==="
echo "警告: 此脚本将回滚所有重构更改！"
read -p "确认继续? (yes/no): " confirm

if [ "$confirm" != "yes" ]; then
  echo "取消回滚"
  exit 0
fi

echo "开始回滚..."

# 停止所有服务
pkill -f "node.*server" || true
pkill -f "tsx.*watch" || true

# 回滚文件
rm -rf src/shared
rm -rf src/manager
rm -f src/machine/app.ts
rm -f src/machine/server.ts
rm -f tests/verify-step*.js

git checkout src/
git checkout tsconfig.json
git checkout package.json

# 重新安装依赖
pnpm install

# 验证
pnpm build

echo "=== 回滚完成 ==="
```

### 6.2 使用方法

```bash
# 赋予执行权限
chmod +x scripts/rollback-refactor.sh

# 执行回滚
./scripts/rollback-refactor.sh
```

## 7. 回滚后处理

### 7.1 回滚后检查

1. **确认服务正常**
   ```bash
   pnpm dev
   pnpm dev:machine
   ```

2. **运行回归测试**
   ```bash
   pnpm test:api
   pnpm test:login
   ```

3. **记录回滚原因**
   - 更新 `docs/重构/rollback-log.txt`
   - 分析失败原因
   - 制定改进计划

### 7.2 重新执行前准备

1. **修复问题**
   - 分析回滚原因
   - 修复相关代码
   - 更新步骤文档

2. **重新验证基线**
   ```bash
   pnpm build
   pnpm test:api
   ```

3. **重新执行**
   - 从失败的步骤重新开始
   - 保持其他步骤不变

## 8. 防止回滚的最佳实践

### 8.1 执行前检查

- [ ] 确认当前代码状态稳定
- [ ] 备份重要数据
- [ ] 确认有足够时间完成验证
- [ ] 准备好回滚方案

### 8.2 分步骤执行

- [ ] 一次只执行一个步骤
- [ ] 每步完成后立即验证
- [ ] 验证通过后再继续下一步
- [ ] 保持清晰的提交历史

### 8.3 验证优先

- [ ] 先运行验证脚本
- [ ] 再进行功能测试
- [ ] 最后进行集成测试
- [ ] 任何失败都立即处理
